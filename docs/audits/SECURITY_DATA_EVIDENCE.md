## Verified strengths and boundaries

- Parameterized SQL, Zod request parsing, bcrypt password verification, hashed refresh tokens, TOTP enrollment/verification, role middleware, Helmet, rate limits and CORS are implemented (`routes/auth.ts`, `middleware/requireAuth.ts`, `index.ts`). AGENTS description of Argon2 does not match the actual bcrypt authentication implementation. These controls do not establish full security assurance.
- Stripe signature verification uses raw bytes, timestamp tolerance and timing-safe comparison; missing signing secret fails closed (`routes/billing.ts:12-78,107-129`; `index.ts:75-84`). Good authenticity groundwork, not billing lifecycle completeness.
- Non-overridable NPO and allergen evaluation exists (`engine/safetyEvaluator.ts:145-177`), with explicit tray NPO denial (`routes/trayruns.ts:343-353`). Admission normalization remains a separate blocker.
- Refresh tokens are hashed in the database (`routes/auth.ts:87-94`); browser access token is memory-only and refresh token uses sessionStorage (`src/security/tokenManager.ts:12-27`). Session revocation, concurrent refresh atomicity and browser XSS resilience still require targeted tests.
- Canonical migrations include table-presence drift checking (`db/migrate.ts:1044-1138`). Table existence is narrower than column/constraint/data correctness.
- Production PHI hosting agreements, vendor contracts, real backup schedule, restore logs, off-host security controls, penetration testing, account recovery, incident exercises and deployed configuration are Unknown. A recorded BAA signee in setup does not prove executed legal agreements or operational compliance.

## Recommended boundary and role reconciliation

Security/database recommendation: internal testing with synthetic records while SEC-01, SEC-02 and CLIN-01 are unresolved. Do not deploy shared tenant hosting. A founder-operated single-facility pilot reduces tenancy complexity but does not excuse authentication, NPO, recovery or privacy controls. Preserve a small core: authorized census and diet maintenance, safe tray workflow, inventory and explicit CSV exchange. Keep live EHR, automated distributor exchange, corporate analytics and self-service billing out of commercial promises until integration evidence exists.

No major implementation changes were made. All acceptance checks above are proposed, not executed. The parent audit may add isolated test results; those must be linked separately rather than inferred from this static review.
